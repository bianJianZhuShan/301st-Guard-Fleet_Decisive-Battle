## 1. 项目概述

### 1.1 技术栈

- **引擎**: Unreal Engine 5.7
- **语言**: C++ + Blueprint
- **网络**: UE5内置网络框架（Listen Server）

## 3. 队伍系统

### 3.1 设计目标

- **统一命名**：使用 `TeamID` 替代不规范的"坐席1/坐席2"、"己方/敌方"
- **可扩展**：支持1v1、2v2、多v多、PvE
- **向后兼容**：保留 `bIsEnemy` 等旧API

### 3.2 TeamID（队伍ID）

| TeamID | 含义 | 颜色 |
|--------|------|------|
| 0 | 蓝方（默认主机） | 蓝色 |
| 1 | 红方（默认客户端） | 红色 |
| 2-7 | 扩展队伍（多v多模式） | 绿/黄/紫/青/橙/粉 |
| -1 | 未分配 | - |
| -2 | 观战者 | - |
| -3 | 中立单位 | 灰色 |
| 100 | 敌对AI（PvE） | 深红色 |

### 3.3 ETacticalSeat（座席）

```cpp
enum class ETacticalSeat : uint8
{
    Seat0,      // 座席0（蓝方，主机）
    Seat1,      // 座席1（红方，客户端）
    Seat2-7,    // 扩展座席
    Spectator,  // 观战者
    None,       // 未分配
    
    // 向后兼容别名
    Player = Seat0,
    AI = Seat1
};
```

### 3.4 API 使用

```cpp
// 设置单位队伍
Unit->SetTeamID(0);  // 蓝方
Unit->SetTeamID(1);  // 红方

// 判断敌友关系
if (FTeamManager::IsHostile(UnitA->TeamID, UnitB->TeamID))
{
    // 可以攻击
}

// 向后兼容
if (Unit->bIsEnemy) { ... }  // 仍然可用
```

## 5. 模型系统

### 5.1 模型类型

| 类型 | 类名 | 用途 |
|------|------|------|
| **静态网格** | `UStaticMesh` | 不需要动画的模型（舰船） |
| **骨骼网格** | `USkeletalMesh` | 需要动画的模型 |

### 5.2 模型导入

1. 将 FBX 文件拖入 `Content/Game/Art/Ships/` 目录
2. 在 UE 编辑器中确认导入成功
3. 右键模型 → Copy Reference 获取资源路径

### 5.3 配置模型

编辑 `ShipDataConfig.h`：

```cpp
FShipMeshConfig FrigateFriendlyMesh(
    TEXT("/Game/Game/Art/Ships/TEXT.TEXT"),  // 己方模型路径
    FVector(1.0f, 1.0f, 1.0f),               // 缩放
    FVector(0.0f, 0.0f, 75.0f),              // 位置偏移
    FRotator(0.0f, 0.0f, 0.0f)               // 旋转偏移
);

FShipMeshConfig FrigateEnemyMesh(
    TEXT("/Game/Game/Art/Ships/text2.text2"), // 敌方模型路径
    FVector(1.0f, 1.0f, 1.0f),
    FVector(0.0f, 0.0f, 75.0f),
    FRotator(0.0f, 0.0f, 0.0f)
);

ShipConfigs.Add(EUnitType::Frigate, FShipDataConfig(
    TEXT("护卫舰"), EUnitType::Frigate,
    80, 15, 2, 1, 4, 2, 2, 3,
    FrigateFriendlyMesh, FrigateEnemyMesh  // 添加模型配置
));
```

### 5.4 调整模型参数

| 参数 | 作用 | 常见调整 |
|------|------|----------|
| `Scale` | 模型缩放 | 模型太大/太小时调整 |
| `Offset` | 位置偏移 | 模型不在格子中心时调整 Z 值 |
| `Rotation` | 旋转偏移 | 模型朝向不对时调整 Yaw |

### 5.5 在UE编辑器中调整模型大小（推荐方法）

模型替换后如果大小不合适，有两种调整方式：

#### 方法一：通过代码配置调整（推荐，一次性生效所有同类型舰船）

编辑 `ShipDataConfig.h` 中对应舰船的 `FShipMeshConfig`：

```cpp
FShipMeshConfig FrigateFriendlyMesh(
    TEXT("/Game/Game/Art/Ships/TEXT.TEXT"),  // 模型路径
    FVector(2.0f, 2.0f, 2.0f),              // ← 缩放：XYZ各放大2倍
    FVector(0.0f, 0.0f, 75.0f),             // ← 偏移：Z方向上移75单位
    FRotator(0.0f, 90.0f, 0.0f)             // ← 旋转：Yaw旋转90度
);
```

**调整步骤：**
1. 修改 `Scale` 的 XYZ 值控制大小（等比缩放就三个值相同）
2. 修改 `Offset` 调整位置（Z值控制上下偏移）
3. 修改 `Rotation` 调整朝向（Yaw=第二个值 控制水平旋转）
4. 重新编译（Ctrl+Shift+B），然后在编辑器中运行查看效果
5. 反复调整直到满意

**常用缩放参考：**
| 效果 | Scale值 |
|------|---------|
| 缩小一半 | `FVector(0.5f, 0.5f, 0.5f)` |
| 原始大小 | `FVector(1.0f, 1.0f, 1.0f)` |
| 放大2倍 | `FVector(2.0f, 2.0f, 2.0f)` |
| 放大5倍 | `FVector(5.0f, 5.0f, 5.0f)` |
| 只加宽 | `FVector(1.0f, 2.0f, 1.0f)` |

#### 方法二：在UE编辑器中调整导入设置

适合一次性调整FBX导入时的基准大小：

1. 在 Content Browser 中找到模型资产（如 `Content/Game/Art/Ships/TEXT`）
2. **双击** 打开 Static Mesh Editor
3. 在左侧 Details 面板中：
   - **Import Uniform Scale**：整体缩放系数（1.0 = 原始大小）
   - 修改后点击 **Reimport** 重新导入
4. 也可以在 Details 面板搜索 **Transform**：
   - **Import Translation**：导入时的位移偏移
   - **Import Rotation**：导入时的旋转偏移

#### 方法三：FBX导入时设置

适合首次导入模型时直接设定：

1. 将 FBX 文件拖入 Content Browser 的 `Content/Game/Art/Ships/` 目录
2. 在弹出的 **FBX Import Options** 对话框中：
   - **Transform** 区域：
     - **Import Uniform Scale**: 填写缩放值（例如 `0.01` 可以把CM单位模型缩到UE单位）
     - **Import Rotation**: 调整导入旋转
   - 点击 **Import** 完成导入

> **提示：** 推荐使用方法一（代码配置），因为它不修改原始资产，便于对不同舰船类型设定不同的大小，且修改后只需重新编译即可生效。

## 6. 开发FAQ

### Q1: 如何修改球体显示范围

球体的大小由舰船的 `MoveRange` 和 `AttackRange` 属性决定。

**方法一：在编辑器中修改**
1. 选中舰船实例
2. 在 Details 面板搜索 `MoveRange` 或 `AttackRange`
3. 修改数值

**方法二：在代码中修改**
编辑 `ShipDataConfig.h` 中对应舰船的配置。

**球体大小计算公式：**
```
球体半径(UE单位) = 范围(格数) × CellSpacing(1000)
```

### Q2: 如何在编辑器中预览网格

1. 在场景中选中 `GridSpaceActor`
2. 在 Details 面板找到 **Grid | Editor Preview**
3. 确保 `bShowGridInEditor` 已勾选
4. 调整 `EditorGridOpacity` 控制透明度

### Q3: AI行为开发

**核心函数位置：** `TacticalGameMode.cpp`

```cpp
void ExecuteAITurn();    // AI回合入口
void AITryMove();        // AI移动逻辑
void AITryAttack();      // AI攻击逻辑
void AIEndTurnIfNeeded(); // 回合结束
```

**改进AI的方向：**

1. **威胁评估系统**
```cpp
float CalculateThreat(AUnitActor* Target) {
    float Threat = 0;
    Threat += Target->AttackDamage * 2;
    Threat += (10 - Target->CurrentHealth);
    Threat -= FVector::Dist(MyPos, Target->GetActorLocation()) / 1000;
    return Threat;
}
```

2. **状态机方式**
```cpp
enum class EAIState { Aggressive, Defensive, Retreating };
```

### Q4: 地图编辑

**快速方法：**
1. 打开现有地图（如 `test-Map02`）
2. 右键 → Duplicate（复制）为新地图
3. 在场景中直接拖拽修改

**部署区域：**
- 己方部署：X=0~2（X=2为前排）
- 敌方部署：X=7~9（X=7为前排）

### Q5: 场景照明

**快速解决方案：**

2. 添加 **Sky Light**（天空光）

**太空场景推荐设置：**

  - Intensity: 3.0
  - Light Color: 浅蓝色 (200, 220, 255)

  - Intensity: 1.0

## 8. UMG事件绑定指南

本节说明如何在UMG Widget Blueprint中绑定现有C++事件。

### 8.1 架构概览

项目提供了 `UTacticalMainMenuWidget` C++基类，Widget Blueprint可继承它来自动或手动绑定按钮事件。

```
UTacticalMainMenuWidget (C++基类)
    └─ HUB_01 (Widget Blueprint)
         ├─ Btn_StartBattle → OnStartBattlePressed()
         ├─ Btn_AIBattle   → OnAIBattlePressed()
         ├─ Btn_HostGame   → OnHostGamePressed()
         └─ Btn_Quit       → OnQuitGamePressed()
                ↓
ATacticalPlayerController (C++控制器)
    ├─ OnStartBattleClicked()
    ├─ OnAIBattleClicked()
    ├─ CreateRoom()
    ├─ JoinGame(IP)
    └─ OnQuitGameClicked()
```

### 8.2 方法A：自动绑定（推荐）

只需按钮命名正确即可自动工作，无需写蓝图逻辑。

**步骤：**

1. **重设父类（Reparent）**
   - 打开 `Content/HUB/HUB_01` Widget Blueprint
   - 点击菜单栏 **File → Reparent Blueprint**
   - 搜索并选择 `TacticalMainMenuWidget`
   - 确认并保存

2. **按钮命名**（在Designer的Details面板顶部修改名称）

   | 按钮名称 | 功能 | 对应C++函数 |
   |---------|------|------------|
   | `Btn_StartBattle` | 开始对战 | `TPC->OnStartBattleClicked()` |
   | `Btn_AIBattle` | AI对战 | `TPC->OnAIBattleClicked()` |
   | `Btn_DeckEditor` | 卡组编辑 | `TPC->OnDeckEditorClicked()` |
   | `Btn_HostGame` | 创建房间 | `TPC->CreateRoom()` |
   | `Btn_JoinGame` | 加入房间 | 打开加入页面 |
   | `Btn_Hotkeys` | 快捷键 | 显示快捷键页 |
   | `Btn_Quit` | 退出游戏 | `TPC->OnQuitGameClicked()` |

3. **编译后即可** — C++的 `NativeConstruct()` 自动查找同名按钮并绑定 `OnClicked`。

### 8.3 方法B：蓝图手动绑定

如果按钮命名不想遵循约定，可在蓝图中手动绑定。

**步骤：**

1. Reparent 同上
2. 在Widget的 **Graph** 视图中操作
3. 选中按钮 → Details面板底部 **Events** 区 → 点击 **On Clicked** 的 `+`
4. 从事件节点拉线，搜索调用对应函数：

```
[On Clicked (按钮)] → [On Start Battle Pressed]
```

这些函数继承自 `TacticalMainMenuWidget` 基类，蓝图中可直接搜索到。

### 8.4 方法C：纯蓝图（不修改父类）

不想修改父类也可以：

1. 按钮的 `On Clicked` 事件中：
2. 添加节点：**Get Owning Player** → **Cast to TacticalPlayerController**
3. 从Cast结果调用目标函数

```
[On Clicked] → [Get Owning Player] → [Cast to TacticalPlayerController]
                                           │
                                           └→ [On Start Battle Clicked]
```

每个按钮对应的函数名（蓝图中显示为空格分隔）：

| 按钮功能 | 蓝图中搜索的函数名 |
|---------|------------------|
| 开始对战 | `On Start Battle Clicked` |
| AI对战 | `On AI Battle Clicked` |
| 卡组编辑 | `On Deck Editor Clicked` |
| 创建房间 | `Create Room` |
| 加入房间 | `Join Game` (需传入String: IP地址) |

### 8.5 显示/隐藏UMG Widget

在C++中创建并显示Widget：

```cpp
// 在PlayerController的BeginPlay中创建Widget
UClass* WidgetClass = LoadClass<UUserWidget>(
    nullptr, TEXT("/Game/HUB/HUB_01.HUB_01_C"));
if (WidgetClass)
{
    UUserWidget* MenuWidget = CreateWidget<UUserWidget>(this, WidgetClass);
    MenuWidget->AddToViewport(100); // ZOrder高 = 最前面
}
```

在蓝图中：
- **显示**: `Add to Viewport` 节点
- **隐藏**: `Remove from Parent` 节点
- **切换**: `Set Visibility` 节点（`Visible` / `Collapsed`）

### 8.6 注意事项

- UMG Widget需要 **UI输入模式** 才能接收按钮点击
- 设置方法: `Set Input Mode UI Only` 或 `Set Input Mode Game and UI`
- 当从菜单进入游戏时，切回 `Set Input Mode Game Only`
- `BindWidgetOptional` 标记意味着按钮可选：即使Widget中没有同名按钮也不会报错
