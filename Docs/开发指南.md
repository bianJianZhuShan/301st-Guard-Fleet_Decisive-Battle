- **语言**: C++ + Blueprint

## 3. 队伍系统

### 3.1 设计目标

- **统一命名**：使用 `TeamID` 替代不规范的"坐席1/坐席2"、"己方/敌方"
- **可扩展**：支持1v1、2v2、多v多、PvE
- **向后兼容**：保留 `bIsEnemy` 等旧API

### 3.2 TeamID（队伍ID）

| TeamID | 含义 | 颜色 |
|--------|------|------|
| 0 | 蓝方（默认主机） | 蓝色 |
| 1 | 红方（默认客户端） | 红色 |
| 2-7 | 扩展队伍（多v多模式） | 绿/黄/紫/青/橙/粉 |
| -1 | 未分配 | - |
| -2 | 观战者 | - |
| -3 | 中立单位 | 灰色 |
| 100 | 敌对AI（PvE） | 深红色 |

### 3.3 ETacticalSeat（座席）

```cpp
enum class ETacticalSeat : uint8
{
    Seat0,      // 座席0（蓝方，主机）
    Seat1,      // 座席1（红方，客户端）
    Seat2-7,    // 扩展座席
    Spectator,  // 观战者
    None,       // 未分配
    
    // 向后兼容别名
    Player = Seat0,
    AI = Seat1
};
```

### 3.4 API 使用

```cpp
// 设置单位队伍
Unit->SetTeamID(0);  // 蓝方
Unit->SetTeamID(1);  // 红方

// 判断敌友关系
if (FTeamManager::IsHostile(UnitA->TeamID, UnitB->TeamID))
{
    // 可以攻击
}

// 向后兼容
if (Unit->bIsEnemy) { ... }  // 仍然可用
```

## 5. 模型系统

### 5.1 模型类型

| 类型 | 类名 | 用途 |
|------|------|------|
| **静态网格** | `UStaticMesh` | 不需要动画的模型（舰船） |
| **骨骼网格** | `USkeletalMesh` | 需要动画的模型 |

### 5.2 模型导入

1. 将 FBX 文件拖入 `Content/Game/Art/Ships/` 目录
2. 在 UE 编辑器中确认导入成功
3. 右键模型 → Copy Reference 获取资源路径

### 5.3 配置模型

编辑 `ShipDataConfig.h`：

```cpp
FShipMeshConfig FrigateFriendlyMesh(
    TEXT("/Game/Game/Art/Ships/TEXT.TEXT"),  // 己方模型路径
    FVector(1.0f, 1.0f, 1.0f),               // 缩放
    FVector(0.0f, 0.0f, 75.0f),              // 位置偏移
    FRotator(0.0f, 0.0f, 0.0f)               // 旋转偏移
);

FShipMeshConfig FrigateEnemyMesh(
    TEXT("/Game/Game/Art/Ships/text2.text2"), // 敌方模型路径
    FVector(1.0f, 1.0f, 1.0f),
    FVector(0.0f, 0.0f, 75.0f),
    FRotator(0.0f, 0.0f, 0.0f)
);

ShipConfigs.Add(EUnitType::Frigate, FShipDataConfig(
    TEXT("护卫舰"), EUnitType::Frigate,
    80, 15, 2, 1, 4, 2, 2, 3,
    FrigateFriendlyMesh, FrigateEnemyMesh  // 添加模型配置
));
```

### 5.4 调整模型参数

| 参数 | 作用 | 常见调整 |
|------|------|----------|
| `Scale` | 模型缩放 | 模型太大/太小时调整 |
| `Offset` | 位置偏移 | 模型不在格子中心时调整 Z 值 |
| `Rotation` | 旋转偏移 | 模型朝向不对时调整 Yaw |

### 5.5 在UE编辑器中调整模型大小（推荐方法）

模型替换后如果大小不合适，有两种调整方式：

#### 方法一：通过代码配置调整（推荐，一次性生效所有同类型舰船）

编辑 `ShipDataConfig.h` 中对应舰船的 `FShipMeshConfig`：

```cpp
FShipMeshConfig FrigateFriendlyMesh(
    TEXT("/Game/Game/Art/Ships/TEXT.TEXT"),  // 模型路径
    FVector(2.0f, 2.0f, 2.0f),              // ← 缩放：XYZ各放大2倍
    FVector(0.0f, 0.0f, 75.0f),             // ← 偏移：Z方向上移75单位
    FRotator(0.0f, 90.0f, 0.0f)             // ← 旋转：Yaw旋转90度
);
```

**调整步骤：**
1. 修改 `Scale` 的 XYZ 值控制大小（等比缩放就三个值相同）
2. 修改 `Offset` 调整位置（Z值控制上下偏移）
3. 修改 `Rotation` 调整朝向（Yaw=第二个值 控制水平旋转）
4. 重新编译（Ctrl+Shift+B），然后在编辑器中运行查看效果
5. 反复调整直到满意

**常用缩放参考：**
| 效果 | Scale值 |
|------|---------|
| 缩小一半 | `FVector(0.5f, 0.5f, 0.5f)` |
| 原始大小 | `FVector(1.0f, 1.0f, 1.0f)` |
| 放大2倍 | `FVector(2.0f, 2.0f, 2.0f)` |
| 放大5倍 | `FVector(5.0f, 5.0f, 5.0f)` |
| 只加宽 | `FVector(1.0f, 2.0f, 1.0f)` |

#### 方法二：在UE编辑器中调整导入设置

适合一次性调整FBX导入时的基准大小：

1. 在 Content Browser 中找到模型资产（如 `Content/Game/Art/Ships/TEXT`）
2. **双击** 打开 Static Mesh Editor
3. 在左侧 Details 面板中：
   - **Import Uniform Scale**：整体缩放系数（1.0 = 原始大小）
   - 修改后点击 **Reimport** 重新导入
4. 也可以在 Details 面板搜索 **Transform**：
   - **Import Translation**：导入时的位移偏移
   - **Import Rotation**：导入时的旋转偏移

#### 方法三：FBX导入时设置

适合首次导入模型时直接设定：

1. 将 FBX 文件拖入 Content Browser 的 `Content/Game/Art/Ships/` 目录
2. 在弹出的 **FBX Import Options** 对话框中：
   - **Transform** 区域：
     - **Import Uniform Scale**: 填写缩放值（例如 `0.01` 可以把CM单位模型缩到UE单位）
     - **Import Rotation**: 调整导入旋转
   - 点击 **Import** 完成导入

> **提示：** 推荐使用方法一（代码配置），因为它不修改原始资产，便于对不同舰船类型设定不同的大小，且修改后只需重新编译即可生效。

## 6. 开发FAQ

### Q1: 如何修改球体显示范围

球体的大小由舰船的 `MoveRange` 和 `AttackRange` 属性决定。

**方法一：在编辑器中修改**
1. 选中舰船实例
2. 在 Details 面板搜索 `MoveRange` 或 `AttackRange`
3. 修改数值

**方法二：在代码中修改**
编辑 `ShipDataConfig.h` 中对应舰船的配置。

**球体大小计算公式：**
```
球体半径(UE单位) = 范围(格数) × CellSpacing(1000)
```

### Q2: 如何在编辑器中预览网格

1. 在场景中选中 `GridSpaceActor`
2. 在 Details 面板找到 **Grid | Editor Preview**
3. 确保 `bShowGridInEditor` 已勾选
4. 调整 `EditorGridOpacity` 控制透明度

### Q3: AI行为开发

**核心函数位置：** `TacticalGameMode.cpp`

```cpp
void ExecuteAITurn();    // AI回合入口
void AITryMove();        // AI移动逻辑
void AITryAttack();      // AI攻击逻辑
void AIEndTurnIfNeeded(); // 回合结束
```

**改进AI的方向：**

1. **威胁评估系统**
```cpp
float CalculateThreat(AUnitActor* Target) {
    float Threat = 0;
    Threat += Target->AttackDamage * 2;
    Threat += (10 - Target->CurrentHealth);
    Threat -= FVector::Dist(MyPos, Target->GetActorLocation()) / 1000;
    return Threat;
}
```

2. **状态机方式**
```cpp
enum class EAIState { Aggressive, Defensive, Retreating };
```

### Q4: 地图编辑

**快速方法：**
1. 打开现有地图（如 `test-Map02`）
2. 右键 → Duplicate（复制）为新地图
3. 在场景中直接拖拽修改

**部署区域：**
- 己方部署：X=0~2（X=2为前排）
- 敌方部署：X=7~9（X=7为前排）

### Q5: 场景照明

**快速解决方案：**
1. 添加 **Directional Light**（定向光源）
2. 添加 **Sky Light**（天空光）
3. 添加 **Sky Atmosphere**（天空大气）

**太空场景推荐设置：**
```
Directional Light:
  - Intensity: 3.0
  - Light Color: 浅蓝色 (200, 220, 255)
  - Cast Shadows: ✓

Sky Light:
  - Intensity: 1.0
  - Source Type: Captured Scene
```

## 8. UMG界面完整教程：从创建到应用

本节详细说明如何创建UMG Widget、将其添加到游戏地图中显示、给按钮绑定游戏事件，以及处理输入模式切换。
所有涉及UE编辑器英文操作的地方均附有中文翻译。

### 8.1 什么是UMG

**UMG**（Unreal Motion Graphics）是UE5的UI框架，用可视化编辑器设计界面，替代传统的HUD Canvas绘制方式。

**对比：**

| 特性 | HUD Canvas绘制（旧） | UMG Widget（新） |
|------|---------------------|------------------|
| 编辑方式 | 纯C++代码 | 可视化拖拽 + 蓝图/C++ |
| 布局 | 手动计算像素坐标 | 锚点自适应布局 |
| 交互 | 手动检测鼠标碰撞 | 内置按钮/输入框事件 |
| 维护难度 | 高 | 低 |

本项目的主菜单（开始界面）正在从HUD Canvas迁移到UMG。

### 8.2 创建Widget Blueprint

如果你已经有 `Content/HUB/HUB_01.uasset`，可跳过此步。

1. 在 **Content Browser**（内容浏览器）中，右键空白区域
2. 选择 **User Interface → Widget Blueprint**（用户界面 → 控件蓝图）
3. 命名为 `HUB_01`（或你喜欢的名称）
4. 双击打开进入 **Widget Designer**（控件设计器）

**Designer界面关键区域：**

| 英文 | 中文 | 说明 |
|------|------|------|
| **Palette**（面板） | 组件面板 | 左侧，可拖拽的UI组件列表 |
| **Hierarchy**（层级） | 层级面板 | 左侧，当前Widget的组件树 |
| **Designer**（设计器） | 设计视图 | 中间，可视化编辑区域 |
| **Details**（细节） | 细节面板 | 右侧，选中组件的属性 |
| **Graph**（图表） | 蓝图图表 | 右上角切换，编写事件逻辑 |

**添加按钮：**

1. 从 **Palette** 面板拖拽 **Button**（按钮）到设计视图
2. 在 **Details** 面板最顶部的名称栏修改按钮名称
3. 在Button内拖入一个 **Text**（文本）组件，设置显示文字
4. 重复以上步骤，添加所有需要的按钮

### 8.4 将Widget添加到游戏地图中

Widget创建好后，需要在游戏运行时将它显示出来。以下提供两种方式。

#### 8.4.1 方式A：通过关卡蓝图（Level Blueprint）添加

适合快速测试，不需要修改C++代码。

1. 打开你的游戏地图（双击 `.umap` 文件）
2. 点击顶部工具栏 **Blueprints → Open Level Blueprint**（蓝图 → 打开关卡蓝图）
3. 在蓝图编辑器中，右键空白区域，添加以下节点：

```
Event BeginPlay（事件：开始运行）
    │
    ├→ Create Widget（创建控件）
    │   - Class（类）: 选择 HUB_01
    │   - Owning Player（所属玩家）: Get Player Controller（获取玩家控制器）, Index = 0
    │   - Return Value（返回值）→ 存入变量 MenuWidget
    │
    ├→ Add to Viewport（添加到视口）
    │   - Target（目标）: MenuWidget
    │   - Z Order: 100（数值越大越靠前）
    │
    └→ Set Input Mode Game And UI（设置输入模式：游戏和UI）
        - Player Controller（玩家控制器）: Get Player Controller, Index = 0
        - In Widget to Focus（聚焦控件）: MenuWidget
        - 勾选 Hide Cursor During Capture = false（捕获时不隐藏光标）
```

**关键节点中英对照：**

| 英文节点名 | 中文 | 作用 |
|-----------|------|------|
| `Event BeginPlay` | 事件：开始运行 | 地图加载完成时触发 |
| `Create Widget` | 创建控件 | 实例化Widget对象 |
| `Add to Viewport` | 添加到视口 | 将Widget显示在屏幕上 |
| `Set Input Mode Game And UI` | 设置输入模式：游戏和UI | 允许鼠标同时操作UI和游戏 |
| `Get Player Controller` | 获取玩家控制器 | 获取本地玩家控制器 |
| `Set Show Mouse Cursor` | 设置显示鼠标光标 | 显示/隐藏鼠标 |

#### 8.4.2 方式B：通过C++代码添加（推荐正式使用）

在 `TacticalPlayerController` 或 `TacticalHUD` 的 `BeginPlay` 中加载Widget：

```cpp
// 加载Widget蓝图类
UClass* MenuWidgetClass = LoadClass<UUserWidget>(
    nullptr, TEXT("/Game/HUB/HUB_01.HUB_01_C"));

if (MenuWidgetClass)
{
    // 创建Widget实例
    UUserWidget* MenuWidget = CreateWidget<UUserWidget>(this, MenuWidgetClass);

    // 添加到视口（Z Order越大越靠前）
    MenuWidget->AddToViewport(100);

    // 设置输入模式为 游戏+UI
    FInputModeGameAndUI InputMode;
    InputMode.SetWidgetToFocus(MenuWidget->TakeWidget());
    InputMode.SetLockMouseToViewportBehavior(EMouseLockMode::DoNotLock);
    SetInputMode(InputMode);
    bShowMouseCursor = true;
}
```

**注意**：路径 `/Game/HUB/HUB_01.HUB_01_C` 中：
- `/Game/` 对应 `Content/` 文件夹
- `.HUB_01_C` 是蓝图类的后缀，固定格式

#### 8.4.3 隐藏/移除Widget

当从主菜单进入游戏时，需要隐藏或移除Widget：

```cpp
// 方法1：隐藏（保留实例，可再次显示）
MenuWidget->SetVisibility(ESlateVisibility::Collapsed);

// 方法2：移除（销毁实例）
MenuWidget->RemoveFromParent();

// 同时切换输入模式回游戏
FInputModeGameOnly InputMode;
SetInputMode(InputMode);
bShowMouseCursor = false;
```

蓝图中对应节点：

| 英文节点名 | 中文 | 作用 |
|-----------|------|------|
| `Set Visibility` | 设置可见性 | `Collapsed`=隐藏, `Visible`=显示 |
| `Remove from Parent` | 从父级移除 | 从视口中移除Widget |
| `Set Input Mode Game Only` | 设置输入模式：仅游戏 | 恢复纯游戏输入 |

### 8.5 给按钮绑定游戏事件

本项目主菜单按钮与C++函数的对应关系：

| 按钮功能 | C++函数（在 `TacticalPlayerController` 中） |
|---------|------------------------------------------|
| 开始对战 | `OnStartBattleClicked()` |
| AI对战 | `OnAIBattleClicked()` |
| 卡组编辑 | `OnDeckEditorClicked()` |
| 创建房间 | `CreateRoom()` |
| 加入房间 | `JoinGame(FString IPAddress)` |
| 退出游戏 | `OnQuitGameClicked()` |

以下提供三种绑定方式，任选其一。

#### 8.5.1 方法A：自动绑定（最简单，需8.3步骤）

前提：已将Widget父类设为 `TacticalMainMenuWidget`（见8.3）。

只需将按钮**重命名**为约定名称，C++基类的 `NativeConstruct()` 会自动绑定 `OnClicked` 事件：

| 按钮名称（在Details面板顶部修改） | 自动绑定的功能 |
|-------------------------------|--------------|
| `Btn_StartBattle` | 开始对战 |
| `Btn_AIBattle` | AI对战 |
| `Btn_DeckEditor` | 卡组编辑 |
| `Btn_HostGame` | 创建房间 |
| `Btn_JoinGame` | 加入房间 |
| `Btn_Hotkeys` | 快捷键 |
| `Btn_Quit` | 退出游戏 |

编译并运行即可，无需写任何蓝图逻辑。

#### 8.5.2 方法B：蓝图手动绑定（灵活，需8.3步骤）

前提：已将Widget父类设为 `TacticalMainMenuWidget`（见8.3）。
适合按钮名称不想遵循约定，或需要添加额外逻辑的情况。

1. 在Widget Blueprint中切换到 **Graph**（图表）视图（右上角标签页）
2. 在 **Designer**（设计器）视图中选中你的按钮
3. 在右侧 **Details**（细节）面板拉到底部，找到 **Events**（事件）区域
4. 找到 **On Clicked**（点击时），点击右边的绿色 **+** 按钮
5. 自动跳转到Graph视图并创建事件节点
6. 从事件节点**拉出线**，搜索并选择对应函数：

```
On Clicked（点击时）
    │
    └→ On Start Battle Pressed（开始对战）
```

**可调用的函数列表**（继承自C++基类，蓝图中直接搜索）：

| 蓝图中搜索 | 中文功能 |
|-----------|---------|
| `On Start Battle Pressed` | 开始对战 |
| `On AI Battle Pressed` | AI对战 |
| `On Deck Editor Pressed` | 卡组编辑 |
| `On Host Game Pressed` | 创建房间 |
| `On Join Game Pressed` | 加入房间 |
| `On Quit Game Pressed` | 退出游戏 |
| `On Confirm Join With IP` | 确认加入（需输入IP地址String） |

#### 8.5.3 方法C：纯蓝图绑定（无需修改父类）

不需要继承C++基类，适合完全在蓝图中操作。

1. 在Widget Blueprint的 **Graph** 视图中
2. 为按钮添加 **On Clicked** 事件（同上方步骤2-5）
3. 添加以下节点链：

```
On Clicked（点击时）
    │
    ├→ Get Owning Player（获取所属玩家）
    │
    ├→ Cast to TacticalPlayerController（转换为战术玩家控制器）
    │
    └→ 调用目标函数，例如：On Start Battle Clicked（开始对战）
```

**各按钮对应的函数名**（蓝图中显示为空格分隔的英文）：

| 按钮功能 | 蓝图中搜索的函数名 |

| 卡组编辑 | `On Deck Editor Clicked` |
| 创建房间 | `Create Room` |
| 加入房间 | `Join Game`（需连接一个String类型的IP地址参数） |
| 退出游戏 | `On Quit Game Clicked` |

**操作中英对照：**

| 英文 | 中文 |
|------|------|
| `Get Owning Player` | 获取所属玩家 |
| `Cast to ...` | 转换为... |
| `On Clicked` | 点击时 |
| `Return Value` | 返回值 |
| `As Tactical Player Controller` | 作为战术玩家控制器 |

### 8.6 输入模式切换

UMG按钮需要正确的输入模式才能接收点击。

| 场景 | 输入模式 | 鼠标光标 | 英文节点名 |
|------|---------|---------|-----------|
| 主菜单显示中 | Game And UI（游戏和UI） | 显示 | `Set Input Mode Game And UI` |
| 进入游戏后 | Game Only（仅游戏） | 隐藏 | `Set Input Mode Game Only` |
| 纯UI弹窗 | UI Only（仅UI） | 显示 | `Set Input Mode UI Only` |

**推荐做法：**
- 主菜单用 `Game And UI`，这样玩家可以同时看到游戏场景和操作UI
- 点击"开始对战"后切换为 `Game Only`
- 暂停菜单弹出时再切回 `Game And UI`

在蓝图中设置：
```
Set Input Mode Game And UI（设置输入模式：游戏和UI）
    - Player Controller: Get Player Controller（获取玩家控制器）
    - In Widget to Focus: 你的Widget引用（可选）
```

### 8.7 常见问题

**Q: 按钮点击没有反应？**
- 检查输入模式是否设为 `Game And UI` 或 `UI Only`
- 检查 `bShowMouseCursor`（显示鼠标光标）是否为 `true`
- 确认按钮的 **Is Enabled**（是否启用）为 `true`
- 确认按钮上方没有其他透明组件挡住点击（检查 **Visibility** 可见性设置）

**Q: Widget不显示？**
- 确认调用了 `Add to Viewport`（添加到视口）
- 检查 **Z Order** 是否被其他Widget覆盖
- 确认Widget的根组件 **Visibility**（可见性）不是 `Collapsed`（折叠/隐藏）

**Q: 找不到 `TacticalMainMenuWidget` 父类？**
- 需要先编译C++代码（关闭UE编辑器 → VS中编译 → 重新打开UE）
- 搜索时输入完整名称 `TacticalMainMenuWidget`

**Q: `BindWidgetOptional` 是什么意思？**
- 表示该按钮变量是**可选绑定**的
- 如果Widget中没有同名按钮，不会报错，只是不会自动绑定
- 如果有同名按钮，会自动绑定 `OnClicked` 事件

**Q: 路径 `/Game/HUB/HUB_01.HUB_01_C` 怎么来的？**
- `/Game/` = `Content/` 文件夹
- `HUB/HUB_01` = 子文件夹和资产名
- `.HUB_01_C` = 蓝图编译后生成的类后缀（固定格式：`.资产名_C`）
- 在UE编辑器中右键资产 → **Copy Reference**（复制引用）可获取完整路径
