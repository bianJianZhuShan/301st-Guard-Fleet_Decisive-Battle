# 太空棋类游戏设计文档

## 1. 项目基础说明

### 1.1 游戏概述
这是一个3D太空战术棋类游戏，融合了象棋、军棋的策略性和太空战斗的科幻感。

### 1.2 核心玩法
- **战场空间**: 10×10×10的立方体空间（共1000个顶点位置）
- **移动机制**: 每个单位可在球形范围内移动到任意顶点
- **行动点系统**: 每回合10点行动点，用于移动和攻击
- **回合制**: 点数耗尽或主动结束回合后切换到下一玩家

### 1.3 游戏模式
- **1v1对战** (v0.0.1优先实现)
- **2v2团队战** (后续版本)
- **3-5人混战** (后续版本)

### 1.4 单位类型
| 单位名称 | 类型 | 定位 | 特点 |
|---------|------|------|------|
| 护卫舰 | 攻击机群 | 轻型快速单位 | 移动范围大，生命值低 |
| 驱逐舰 | 维修舰 | 支援单位 | 可修复友军 |
| 轻型巡洋舰 | 盾舰 | 防御单位 | 高护甲值 |
| 重型巡洋舰 | 炮舰 | 主力输出 | 攻击范围和伤害平衡 |
| 战列巡洋舰 | 重型炮舰 | 重型输出 | 高伤害，移动慢 |
| 超级战列舰 | 攻击母舰 | 旗舰单位 | 综合能力强，行动点消耗大 |

### 1.5 自定义系统（后续版本）
- **卡组系统**: 玩家可自定义舰队配置
  - 使用点数限制而非数量限制
  - 标准卡组总点数 ≤ 50
  - 允许"精英流"或"海量流"配置
- **模块系统**: 为单位装配火炮、装甲、动力等模块
- **卡槽限制**: 不同单位有不同数量和类型的卡槽

### 1.6 单位点数成本（v0.0.2+）
| 单位类型 | 点数成本 | 说明 |
|---------|---------|------|
| 护卫舰 | 1点 | 轻型单位 |
| 驱逐舰 | 2点 | 支援单位 |
| 轻型巡洋舰 | 3点 | 防御单位 |
| 重型巡洋舰 | 5点 | 主力输出 |
| 战列巡洋舰 | 7点 | 重型火力 |
| 超级战列舰/航母 | 10点 | 旗舰单位 |

**标准卡组示例**（总计50点）:
- 5护卫舰 + 3驱逐 + 2轻巡 + 1重巡 + 2战巡 + 1战列 = 50点

**极端卡组示例**（总计50点）:
- 20驱逐 + 1战列 = 50点（数量多但单体弱）

## 4. 核心设计决策

### 4.0 先手平衡机制

#### 问题
回合制游戏中，先手玩家通常具有优势：
- 先攻击，可能先击杀敌方单位
- 先占据有利位置
- 掌握主动权

#### 解决方案

**主要机制：自动反击系统** ⭐
- 后手玩家可以预留反击点数
- 先手玩家贸然进攻会被反击
- 天然平衡先手优势

**辅助机制：后手资源补偿**
- 后手玩家第一回合获得 **12点行动点**（比先手多2点）
- 用于布防和预留反击点数
- 类似《炉石传说》的"后手抽牌"机制

**设计理由**:
- 鼓励先手玩家谨慎行动
- 给后手玩家足够的防守资源
- 保持游戏公平性

**测试指标**:
- 目标先手胜率：50-55%
- 如果先手胜率>60%，考虑增加后手补偿
- 如果后手胜率>55%，考虑减少补偿

### 4.0.1 地图密度与单位数量

#### 当前设计
- 地图：10×10×10 = 1000个点
- v0.0.1：双方各3个单位（密度0.6%）
- v0.0.2标准卡组：双方各15个单位（密度3%）

#### 密度分析

**3个单位（v0.0.1）**:
- 密度：0.6%
- 评估：✅ 非常宽松，适合测试
- 特点：有大量机动空间，战术纵深足够

**15个单位（标准卡组）**:
- 密度：3%
- 评估：✅ 合适，不拥挤
- 特点：有足够战术空间，不会第一回合就开打

**21个单位（极端卡组：20驱逐+1战列）**:
- 密度：4.2%
- 评估：⚠️ 开始拥挤，需要测试
- 风险：可能变成"混战"而非"战术"

#### 解决方案：分区部署

即使地图是10×10×10，也限制初始部署区域：

```
己方部署区：X=0-2（3×10×10 = 300个点）
中立区：X=3-6（4×10×10 = 400个点）
敌方部署区：X=7-9（3×10×10 = 300个点）
```

**优势**:
- 即使单位多，也不会第一回合就混战
- 有"前线推进"的感觉
- 符合太空战争的"舰队对峙"感
- 为战术机动留出空间

### 4.0.2 初始位置生成系统

#### 三种方案对比

**方案A：固定位置（v0.0.1采用）** ⭐
- 类似国际象棋的固定开局
- 简单、易于理解
- 玩家可以形成固定战术
- 竞技公平性高

**示例布局（3单位）**:
```
单位1：(5, 5, 0) - 中央前排
单位2：(3, 5, 1) - 左侧中排
单位3：(7, 5, 1) - 右侧中排
```

**方案B：随机生成位置（后续考虑）**
- 高价值单位必须在后排（Z=2）
- 中价值单位在中排（Z=1-2）
- 低价值单位在前排（Z=0-2）
- 增加变化性和探索感
- 但可能出现极端不利开局

**方案C：玩家自定义站位（v0.0.2实现）** ⭐⭐⭐
- 游戏开始前进入"部署阶段"
- 玩家在己方部署区（10×10×3）内拖拽单位
- 双方同时部署（看不到对方）
- 策略深度最高
- 可以保存"部署方案"模板

**方案D：混合方案（v0.1.0）**
- 提供三种模式供玩家选择：
  1. 标准部署（固定位置）
  2. 自定义部署（完全自由）
  3. 随机部署（系统随机）
- 玩家在创建房间时选择

#### 实现路线图
- **v0.0.1**：只实现固定位置（方案A）
- **v0.0.2**：实现自定义部署（方案C）
- **v0.1.0**：实现混合方案（方案D）

## 5. 核心机制详解

### 5.1 视角控制系统 ⭐

#### 俯瞰视角（宏观操作模式）
**特点**:
- 从上方45度角俯视整个战场
- 可以看到所有己方和敌方单位
- 适合进行战略规划和整体布局

**操作**:
- WASD: 平移相机位置
- 鼠标滚轮: 缩放视野
- 鼠标右键拖拽: 旋转视角
- 单击单位: 选中单位
- 双击单位: 切换到单位视角

**相机参数**:
- 高度: 战场上方约20个单位
- 俯角: 45度
- FOV: 90度
- 移动速度: 可调节

#### 单位视角（精细操作模式）
**特点**:
- 相机位于单位右侧斜后方
- 类似第三人称视角
- 可以精确观察单位周围环境
- 适合进行精细的移动和攻击操作

**操作**:
- WASD: 围绕单位移动相机
- 鼠标: 控制视角方向
- 空格键: 快速返回俯瞰视角
- Tab键: 切换到下一个己方单位

**相机参数**:
- 距离: 单位后方约5个单位
- 高度: 单位上方约2个单位
- 偏移: 右侧约2个单位
- FOV: 75度

#### 视角切换动画
- 使用UE5的`SetViewTargetWithBlend`
- 过渡时间: 0.5秒
- 缓动函数: EaseInOut
- 保持平滑流畅的切换体验

---

### 5.2 自动反击系统 ⭐

#### 触发条件
1. 当前是敌方回合
2. 敌方单位移动或攻击后进入我方单位攻击范围
3. 我方单位有足够的预留反击点数
4. 我方单位与敌方单位之间有视线（无障碍物）

#### 反击机制
**点数消耗**:
- 每次自动反击消耗2点行动点（与主动攻击相同）
- 玩家可以在回合结束时选择预留多少点数用于反击
- 预留点数不足时，不会触发反击

**反击优先级**:
- 如果多个敌方单位同时进入范围，优先攻击生命值最低的
- 如果生命值相同，优先攻击距离最近的

**反击次数限制**:
- 每个单位在敌方回合最多触发3次反击
- 避免无限反击导致游戏失衡

**UI提示**:
- 触发反击时显示特效和音效
- 显示反击伤害数字
- 在战斗日志中记录反击事件

#### 战术意义
- 鼓励玩家预留点数进行防守
- 增加进攻方的风险
- 提供更多战术选择（全力进攻 vs 保守防守）

---

### 5.3 视线检测系统 ⭐

#### 检测机制
**实现方式**:
- 使用UE5的`LineTraceSingleByChannel`从攻击者到目标进行射线检测
- 如果射线碰到障碍物，则无法攻击
- 如果射线直接命中目标，则可以攻击

**检测参数**:
- 起点: 攻击者单位中心点
- 终点: 目标单位中心点
- 碰撞通道: 自定义"Combat"通道
- 忽略: 攻击者自身和友方单位

**障碍物类型**:
- 小行星（完全阻挡）
- 能量护盾（阻挡攻击但不阻挡移动）
- 其他单位（大型单位可能阻挡视线）

#### 视觉反馈
**可攻击目标**:
- 显示红色瞄准线
- 目标单位红色高亮
- 显示预计伤害数值

**不可攻击目标**:
- 显示灰色虚线
- 显示阻挡视线的障碍物
- UI提示"视线被阻挡"

#### 战术意义
- 增加地形和位置的重要性
- 鼓励使用掩体和障碍物
- 提供更真实的太空战斗体验

---

### 5.4 方位伤害系统（后续版本）

#### 伤害修正
**基础概念**:
- 不同方位攻击造成不同伤害
- 鼓励侧翼包抄和背后偷袭
- 增加战术深度

**方位定义**:
- **正面** (前方120度扇形): 基础伤害 × 100%
- **侧面** (左右各60度扇形): 基础伤害 × 125%
- **背面** (后方120度扇形): 基础伤害 × 150%

**计算方法**:
```cpp
// 计算攻击者到目标的方向向量
FVector AttackDirection = (Target->GetActorLocation() - Attacker->GetActorLocation()).GetSafeNormal();
// 计算目标的朝向向量
FVector TargetForward = Target->GetActorForwardVector();
// 计算夹角
float DotProduct = FVector::DotProduct(AttackDirection, TargetForward);
// 根据夹角判断方位
if (DotProduct > 0.5f) // 正面
    DamageMultiplier = 1.0f;
else if (DotProduct < -0.5f) // 背面
    DamageMultiplier = 1.5f;
else // 侧面
    DamageMultiplier = 1.25f;
```

**视觉反馈**:
- 背后攻击显示"背刺！"特效
- 侧面攻击显示"侧击！"提示
- 伤害数字颜色不同（正面白色，侧面黄色，背面红色）

**战术意义**:
- 鼓励包抄和迂回战术
- 增加单位朝向的重要性
- 提供更丰富的战术选择
